El lenguaje SQLThe SQL language

SQL (Structured Query Language, lenguaje de consulta estructurado) es el lenguaje estándar de las bases de datos relacionales, normalizado por ANSI e ISO. Su característica principal es que es declarativo: quien lo escribe indica qué quiere, no cómo ni dónde conseguirlo, y es el SGBD quien decide cómo hacerlo. Por eso se considera un lenguaje de cuarta generación, lo más cercano posible al lenguaje natural.SQL (Structured Query Language) is the standard language of relational databases, standardised by ANSI and ISO. Its main feature is that it is declarative: whoever writes it states what they want, not how or where to get it, and the DBMS decides how to do it. That is why it is considered a fourth-generation language, as close to natural language as possible.

Normas de escrituraWriting rules

  • Toda instrucción termina en punto y coma (;). Es lo que le dice al SGBD dónde acaba el comando.
  • Every statement ends with a semicolon (;). It tells the DBMS where the command ends.
  • No se distingue entre mayúsculas y minúsculas en las palabras reservadas: select y SELECT son lo mismo.
  • Reserved words are not case-sensitive: select and SELECT are the same thing.
  • Por convención, las palabras reservadas van en mayúsculas y los nombres que ponemos nosotros (tablas, columnas…) en minúsculas. Así se lee mucho mejor.
  • By convention, reserved words go in capitals and the names we choose (tables, columns…) in lower case. It makes reading much easier.
  • Un comando puede ir seguido de espacios o saltos de línea, y se puede tabular para dejar clara su estructura.
  • A command can be followed by spaces or line breaks, and it can be indented to make its structure clear.
  • Los comentarios de una línea empiezan por -- (con un espacio detrás) y los de varias líneas van entre /* y */.
  • Single-line comments start with -- (with a space after) and multi-line ones go between /* and */.

Decisiones de diseñoDesign decisions

  • Orden de creación: primero las tablas que no apuntan a ninguna (examenes, alumnos, practicas, profesores) y después las tablas de unión. Si un FOREIGN KEY apunta a una tabla que aún no existe, da error.
  • Creation order: first the tables that point to none (exams, students, practicals, teachers) and then the junction tables. If a FOREIGN KEY points to a table that does not exist yet, it fails.
  • Claves: las tablas de unión tienen clave primaria compuesta formada por las dos claves ajenas. El esquema ya trae claves naturales (matrícula, código, DNI), así que aquí las respetamos en lugar de añadir un id artificial.
  • Keys: the junction tables have a composite primary key made of the two foreign keys. The schema already brings natural keys (student number, code, ID number), so here we keep them instead of adding an artificial id.
  • Tipos: CHAR para valores de longitud fija (DNI, código), VARCHAR para textos, TINYINT UNSIGNED para un número pequeño y positivo, DECIMAL(4,2) para notas con decimales y ENUM para la dificultad.
  • Types: CHAR for fixed-length values (ID number, code), VARCHAR for text, TINYINT UNSIGNED for a small positive number, DECIMAL(4,2) for grades with decimals and ENUM for the difficulty.
  • Restricciones: NOT NULL donde el dato es imprescindible, un CHECK para que las notas estén entre 0 y 10, y claves ajenas con ON DELETE CASCADE en las tablas de unión: si desaparece un examen o un alumno, sus filas de unión ya no tienen sentido. With teachers we use RESTRICT: we do not want deleting a teacher to take with it the practicals they designed.
