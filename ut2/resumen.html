01 — IntroducciónIntroduction

Del mundo real al modeladoFrom the real world to modelling

Una base de datos representa la información contenida en algún dominio del mundo real. Diseñarla consiste en extraer todos los datos relevantes de un problema.A database represents the information held in some real-world domain. Designing one means extracting all the relevant data from a problem.

Quedarse conKeep

Los datos esenciales para la base de datos.The data essential to the database.

DescartarDiscard

Lo que no es de utilidad para el problema.Whatever isn't useful for the problem.

Un análisis en profundidad del problema, y una vez extraídos los datos: modelado de datos.An in-depth analysis of the problem, and once the data is extracted: data modelling.

01 — ModeladoModelling

LÓGICOLOGICAL

Más técnico; depende del tipo de BBDD. Estructura los datos y sus relaciones. Ej.: modelo relacional.More technical; depends on the DBMS type. Structures the data and its relationships. E.g.: the relational model.

FÍSICOPHYSICAL

Cómo se almacenan los datos: ficheros, registros, tablas...How the data is stored: files, records, tables...

Modelado: proceso de creación de una representación visual que define un sistema de información.Modelling: the process of creating a visual representation that defines an information system.

01 — Interacción entre modelosInteraction between models

Quién trabaja con cada modeloWho works with each model

El usuario experto y el diseñador construyen juntos el modelo conceptual; el programador lo traduce al modelo lógico; el administrador lo lleva al modelo físico. Los tres parten del mismo dominio del problema.The expert user and the designer build the conceptual model together; the programmer translates it into the logical model; the administrator takes it to the physical model. All three start from the same problem domain.

02 — El modelo entidad-relaciónThe entity-relationship model

Un modelo de datos abstractoAn abstract data model

El modelo E/R nos permite representar de manera conceptual una base de datos. Se compone de un diagrama entidad-relación y sus restricciones asociadas.The E/R model lets us represent a database conceptually. It's made up of an entity-relationship diagram and its associated constraints.

02.1 — EntidadEntity

Aquello sobre lo que guardamos datosWhatever we store data about

ALUMNO

Representación física o abstracta. Nombre representativo y único.A physical or abstract representation. A representative, unique name.

ASIGNATURA

No se puede repetir dentro del mismo diagrama.Can't be repeated within the same diagram.

Se representa con un rectángulo que contiene el nombre del elemento del que queremos guardar información.Represented by a rectangle containing the name of the element we want to store information about.

02.1 — Entidad débil y fuerteWeak and strong entities

Cuando una depende de la otraWhen one depends on the other

Fuerte (p. ej. FACTURA): existe por sí misma. Débil (rectángulo doble, p. ej. LÍNEA DE FACTURA o CUENTA/TRANSACCIÓN): su existencia depende de una entidad fuerte asociada.Strong (e.g. INVOICE): exists on its own. Weak (double rectangle, e.g. INVOICE LINE or ACCOUNT/TRANSACTION): its existence depends on an associated strong entity.

02.2 — AtributosAttributes

Cualidades propias de una entidadAn entity's own qualities

ALUMNO tiene nombre y apellidos. No tienen existencia propia: sólo tienen sentido dentro de una entidad (o de una relación).STUDENT has a first name and surname. They have no existence of their own: they only make sense inside an entity (or a relationship).

NormalNormal

Línea continua. Siempre tiene valor.Solid line. Always has a value.

OpcionalOptional

Línea de puntos. Su valor puede ser desconocido (p. ej. un segundo teléfono).Dotted line. Its value may be unknown (e.g. a second phone number).

02.2 — Clave primariaPrimary key

Identifica cada ejemplar sin ambigüedadIdentifies each instance unambiguously

SIMPLESIMPLE

ALUMNO — DNI

Un único atributo basta para identificar cada alumno.A single attribute is enough to identify each student.

COMPUESTACOMPOSITE

CUENTA BANCARIA

Necesita varios atributos juntos: código de banco + código de oficina + código de cuenta.Needs several attributes together: bank code + branch code + account code.

A veces un solo atributo no basta para identificar todas las ocurrencias de una entidad, y hay que construir una clave con varios atributos en un orden determinado.Sometimes a single attribute isn't enough to identify every occurrence of an entity, so a key must combine several attributes in a set order.

03 — RelaciónRelationship

Un vínculo con nombre entre entidadesA named link between entities

Una relación es la asociación o vínculo entre ocurrencias de varias entidades. Se representa con un rombo, e identificada con un nombre casi siempre verbal.A relationship is the association or link between occurrences of several entities. It's drawn as a diamond, named with an almost always verbal name.

04 — CardinalidadCardinality

Cuántas instancias participanHow many instances participate

La cardinalidad representa la participación entre entidades: el número de instancias de una respecto a otra, y viceversa. ¿Un cliente genera una factura o muchas? ¿Una factura puede tener uno o varios clientes?Cardinality represents the participation between entities: how many instances of one relate to the other, and vice versa. Does a customer generate one invoice or many? Can an invoice have one customer or several?

04 — Tipo de correspondenciaCorrespondence type

1:1, 1:N o N:M1:1, 1:N or N:M

1:1

ENTREVISTADOR — EQUIPO. Dirige a uno, y sólo a uno.INTERVIEWER — TEAM. Manages one, and only one.

1:N

CLIENTE — FACTURA. Un cliente genera muchas facturas.CUSTOMER — INVOICE. A customer generates many invoices.

N:M

ALUMNO — ASIGNATURA. Muchos alumnos por asignatura y viceversa.STUDENT — SUBJECT. Many students per subject and vice versa.

Más ejemplos: DEPARTAMENTO-EMPLEADO (1:N), MÚSICO-INSTRUMENTO (N:M), CLIENTE-CARTERA DE INVERSIÓN (1:1). ⚠ Aviso: si hace falta una segunda N, se transforma en M por convenio (N:M) — el significado no cambia.More examples: DEPARTMENT-EMPLOYEE (1:N), MUSICIAN-INSTRUMENT (N:M), CUSTOMER-INVESTMENT PORTFOLIO (1:1). ⚠ Note: if a second N is needed, it becomes M by convention (N:M) — the meaning doesn't change.

04 — Participaciones (modalidad)Participations (modality)

El mínimo y el máximo por entidadThe minimum and maximum per entity

(0,1) alguna vez o ninguna · (1,1) obligatoriamente una · (1,N) al menos una, sin límite · (0,N) ninguna limitación. La cardinalidad general se obtiene tomando el máximo de cada lado.(0,1) at most once, maybe never · (1,1) exactly one, mandatory · (1,N) at least one, no upper limit · (0,N) no limit at all. The overall cardinality is the maximum on each side.

04 — Cómo funcionaHow it works

Del enunciado al diagrama E/RFrom the statement to the E/R diagram

  1. RequisitosRequirements — descripción textual del problema: reglas, forma de trabajar.— a textual description of the problem: its rules, how things work.
  2. AnalizarAnalyse — lista de sustantivos y verbos que aparecen.— list the nouns and verbs that appear.
  3. Entidad o atributosEntity or attributes — los sustantivos son posibles entidades o atributos.— the nouns are possible entities or attributes.
  4. VerbosVerbs — los verbos son posibles relaciones.— the verbs are possible relationships.
  5. CardinalidadCardinality — se determina analizando las frases del enunciado.— worked out by analysing the statement's sentences.
  6. Diagrama E/RE/R diagram — se elabora con todo lo anterior.— built from everything above.
  7. ComplementoComplement — se añaden listas de atributos y restricciones que el diagrama no puede reflejar.— add attribute lists and constraints the diagram can't show.
04.1 — Atributos de una relaciónRelationship attributes

Un dato que no es de ninguna entidadData that belongs to neither entity

SOCIO recibe en préstamo LIBRO. Queremos guardar la fecha del préstamothe loan date — ¿en cuál de los dos la metemos?MEMBER borrows BOOK. We want to store the loan date — which of the two do we put it in?

En SOCIOIn MEMBER

✕ Impediría que un socio tomara más de un libro en préstamo.✕ Would stop a member from borrowing more than one book.

En LIBROIn BOOK

✕ Impediría que un libro fuera prestado más de una vez.✕ Would stop a book from being lent out more than once.

✓ Afecta a ocurrencias de ambas entidades, así que debe figurar en la relación.✓ It affects occurrences of both entities, so it belongs in the relationship.

04.2 — EjemploExample

Del enunciado al diagrama E/RFrom the statement to the E/R diagram

«Una empresa vende productos a varios clientes. Se necesita conocer los datos personales de los clientes (nombre, apellidos, DNI, dirección y fecha de nacimiento). Cada producto tiene un nombre, un código y un precio unitario. Un cliente puede comprar varios productos, y un mismo producto puede ser comprado por varios clientes. Los productos son suministrados por diferentes proveedores; un producto sólo puede ser suministrado por un proveedor, y un proveedor puede suministrar diferentes productos. De cada proveedor se desea conocer el NIF, nombre y dirección.»«A company sells products to several customers. We need the customers' personal data (name, surname, ID number, address and date of birth). Each product has a name, a code and a unit price. A customer can buy several products, and the same product can be bought by several customers. Products are supplied by different suppliers; a product can only be supplied by one supplier, and a supplier can supply different products. For each supplier we want their tax ID, name and address.»

04.2 — Ejemplo resueltoWorked example

Clientes, productos y proveedoresCustomers, products and suppliers

CLIENTE — compra (N:M) — PRODUCTO — suministra (1:N) — PROVEEDOR. Claves: DNI, código y NIF respectivamente.CUSTOMER — buys (N:M) — PRODUCT — supplies (1:N) — SUPPLIER. Keys: ID number, code and tax ID respectively.

05 — Diagrama E/R extendidoExtended E/R diagram

Generalización / especializaciónGeneralisation / specialisation

Relación entre un tipo genérico (supertiposupertype) y tipos más concretos (subtipossubtypes): "es un" o "es un tipo de".A relationship between a generic type (supertype) and more specific types (subtypes): "is a" or "is a type of".

GENERALIZACIÓNGENERALISATION

Varios tipos comparten atributos: creamos un supertipo con esos atributos comunes.Several types share attributes: we create a supertype with those common attributes.

ESPECIALIZACIÓNSPECIALISATION

Una entidad tiene atributos que sólo tienen sentido para algunos ejemplares: definimos subtipos.An entity has attributes that only make sense for some instances: we define subtypes.
