01 — El modelo relacional01 — The relational model

Seis propiedades de toda tablaSix properties of every table

1. Nombre únicoUnique name

Cada tabla tiene un nombre distinto.Every table has a distinct name.

2. Un valor por celdaOne value per cell

Nada de listas dentro de una celda.No lists inside a cell.

3. Atributos distintosDistinct attributes

No se repite un nombre de columna en la misma tabla.A column name isn't repeated within a table.

4. Sin tuplas duplicadasNo duplicate tuples

Cada fila es única: por eso toda tabla necesita una clave.Every row is unique: that's why every table needs a key.

5. Orden de columnas libreColumn order is free

Se accede por nombre, no por posición.You access by name, not by position.

6. Orden de filas libreRow order is free

No hay «primera» fila con significado; se ordena al consultar.There's no meaningful “first” row; you sort when querying.

Si una tabla rompe alguna de las seis, no es una relación en sentido estricto.If a table breaks any of the six, it isn't a relation in the strict sense.

02 — Claves02 — Keys

Cuatro tipos de claveFour kinds of key

CANDIDATACANDIDATE

Atributo o conjunto que identifica cada fila sin ambigüedad. Toda tabla tiene al menos una.Attribute or set that identifies each row unambiguously. Every table has at least one.

PRIMARIAPRIMARY

La candidata elegida. Única y nunca nula. Solo una por tabla.The chosen candidate. Unique and never null. Only one per table.

ALTERNATIVAALTERNATE

Las candidatas no elegidas. En SQL: UNIQUE NOT NULL.The candidates not chosen. In SQL: UNIQUE NOT NULL.

FORÁNEAFOREIGN

Atributo que apunta a la clave primaria de otra tabla (o de la misma). Puede ser nula.Attribute pointing to another table's primary key (or the same table's). It can be null.

Elegir la primaria depende del contexto: corta, estable y siempre con valor. Si ninguna candidata sirve, se crea una artificial (id).Choosing the primary key depends on context: short, stable and always present. If no candidate fits, an artificial one (id) is created.

02 — Claves02 — Keys

La clave foránea en acciónThe foreign key in action

  • Cada jugador guarda solo el número de su equipo: el nombre y la ciudad no se repiten.
  • Each player stores only the number of their team: the name and city aren't repeated.
  • La flecha va de la foránea a la primaria a la que apunta.
  • The arrow goes from the foreign key to the primary key it points to.
  • NULL no es 0 ni vacío: es ausencia de valor. Una foránea nula significa «todavía sin equipo».
  • NULL is neither 0 nor empty: it's the absence of a value. A null foreign key means “no team yet”.

Reglas que impone el modeloRules the model imposes

PRIMARY KEYIdentifica la fila: valores únicos y nunca nulos.Identifies the row: unique, never-null values.

03 — Restricciones03 — Constraints

Integridad referencial: borrar y modificarReferential integrity: deleting and updating

NO ACTION / RESTRICT

Rechaza la operación si hay filas que dependen de la clave afectada. Es la política por defecto.Rejects the operation if rows depend on the affected key. The default policy.

CASCADE

Propaga el cambio: al borrar la principal, se borran las dependientes; al cambiar la clave, se actualizan.Propagates the change: deleting the main row deletes the dependents; changing the key updates them.

SET NULL

Las dependientes siguen existiendo con la foránea a NULL. Solo si admite nulos.Dependents survive with the foreign key set to NULL. Only if it allows nulls.

SET DEFAULT

Las dependientes pasan a un valor por defecto (que debe existir en la principal).Dependents switch to a default value (which must exist in the main table).

Regla práctica: lo débil depende de lo fuerte, así que un hijo de empleado usa CASCADE; un alquiler no debería desaparecer con su cliente.Rule of thumb: the weak depends on the strong, so an employee's child uses CASCADE; a rental shouldn't vanish with its customer.

  1. El modelo relacionalThe relational model organiza los datos en tablas de filas (tuplas) y columnas (atributos), cada una con su dominio.organises data into tables of rows (tuples) and columns (attributes), each with its domain.
  2. Las clavesKeys identifican filas (candidata, primaria, alternativa) y enlazan tablas (foránea, que puede ser nula).identify rows (candidate, primary, alternate) and link tables (foreign, which can be null).
